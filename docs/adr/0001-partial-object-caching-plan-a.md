# 部分对象缓存采用分段位图与对齐回源

本轮设计以 Plan A 为目标：对象按 segment 分组，各段用位图记录完整 chunk 的覆盖情况，并允许将回源范围向 chunk 边界扩展；客户端仍收到原始请求范围。不引入独立 manifest 文件，覆盖信息放在缓存内部元数据中。相对于每块独立探测，位图用于批量判断覆盖和规划缺块回源；实际块定位与读取有效性检查仍由缓存目录及数据读取路径承担。

用户已经允许扩大回源范围，在访谈中确认以下约束，并调用 to-spec 进入规格阶段。本 ADR 记录已接受的设计；发布规格不等于执行部署或合并。

## 已确认约束

- 完整接收且校验通过的内存块可以供其他请求命中，不要求每块同步落盘。允许进程崩溃后丢缓存，但恢复后不得将缺失、截断或错误版本的数据视为有效内容。这不等于已经同意正常重启清空缓存。
- 首版统一分块缓存用于具有强 ETag、总长度可确认且满足共享缓存规则的普通 GET 及单区间 Range 请求；支持开放结尾及后缀范围。无强 ETag、多区间以及客户端条件请求先透传。
- PURGE 成功返回后，新请求不能命中清理前的缓存代次，旧回源任务不得重新发布旧代次。已经开始发送的响应允许继续完成；磁盘旧数据可延后回收，不要求同步物理擦除。
- 首版固定 1 MiB/chunk、64 chunk/segment，每个 64 MiB 分段使用一个 64 bit 覆盖位图，暂不增加可调配置。对象末块按真实长度处理。
- 本次格式升级允许旧缓存失效，不迁移旧缓存内容；部署会经历冷缓存回源。
- 正常退出并完成可靠保存后，重启应能复用部分对象缓存。异常退出后，无法证明一致性的部分对象缓存允许整体失效，首版不做逐块抢救；恢复不能仅依赖正常退出标志。
- 位图允许因淘汰或覆盖而暂时高估覆盖范围，但实际读取仍必须验证数据。读不到块时按 miss 修正位图并补块，修正不得误清除并发重新填充的有效块。
- 对象版本变化不触发本次请求重试，后续请求按新版本重建缓存。若本次响应所需的旧版本字节仍全部可获得，应继续发送旧版本，不因发现源站已有新版而中断。
- 若本次响应缺少旧版本块且源站无法提供该版本，终止本次传输，不重试、不混合新旧版本；后续请求按新版本重建缓存。
- 普通 GET 与 Range 必须双向复用符合部分对象缓存准入条件的对象数据、位图和在途回源，不采用分别保存完整对象和分块对象的隔离方案。客户端响应各自生成，普通 GET 返回完整响应，Range 返回请求的范围，不直接回放共享回源的响应头。
- 必须支持 RWW：验证上游响应头中的版本和范围后，当前回源已收到的字节可边写边供请求读取，不等待整个 chunk 收齐才输出，也不保留响应的最后一个字节。单字节及小 Range 在所需字节到齐后即可完成。RWW 的临时可读状态与已完成位图区分；只有完整且校验成功的 chunk 才能发布为普通缓存命中。后续失败使未完成 chunk 不置位，并通知仍缺少所需字节的读者失败；已经完成的响应不能撤回成功。
- 客户端正常完成或断开后，若仍有其他请求需要共享回源的数据，继续获取；没有请求需要时，已经开始的当前 chunk 独立填充并校验，完成后不再开始后续 chunk 或新回源请求。没有已开始块的任务立即取消。当前块仍受任务超时、服务关闭、存储错误和 PURGE 发布围栏约束；失败块不置位，已完整提交的块保留。
- 普通 GET 完全冷缓存且没有可复用在途任务时，一次普通 GET 回源，边接收边分块写入并提供 RWW；已有部分数据或在途任务时，复用现有内容及任务，仅对缺块执行对齐 Range 回源，合并相邻缺块。

## 2026-11-03：响应完成与当前块填充分开

用户选择“流式发送＋独立完成当前块填充”，替代此前“最后订阅者离开就立即取消全部未完成填充”的约束。1 MiB 是缓存与回源对齐单位，不是客户端发送前必须积攒的字节数；当前块收尾也不意味着无人需要时仍读完两个 chunk 的合并响应或整个普通 GET。

客户端完成与缓存提交是两件事：不能为了保证缓存块完成而扣留客户端最后一个字节，也不能在客户端已经读满响应后，追溯报告对齐尾部的错误。对齐尾部失败时不发布该块；还在等待自身范围字节的读者仍须失败。该选择参考 [ATS Slice 的流式发送与当前块收尾](https://docs.trafficserver.apache.org/en/10.2.x/admin-guide/plugins/slice.en.html)，不将 Slice 插件等同于历史 Plan A 位图提案，也不引入后台补全对象或预取。

## 后续规格的验收重点

- 已确认测试入口：真实 HTTP 请求为主要验收入口，观察响应字节、头部、回源次数和 RWW 时序；磁盘错误、并发竞争与恢复仅补充现有缓存接口测试，不为测试扩展生产 HTTP API。
- 真实 HTTP 下验证普通 GET 与 Range 双向复用、精确字节内容及各自的响应头。
- 慢速源站下验证 chunk 未收齐前即可 RWW 输出；并发 GET/Range 不重复获取同一在途数据，慢客户端或首个客户端退出不能错误终止其他读者。
- 验证单字节请求提前完整返回后，当前块仍可被后续请求共享并最终命中；最后读者离开后只完成已经开始的当前块，未开始的后续块没有新增回源。尾部失败不能污染缓存，且不能把已经完成的小范围响应改判为失败。
- 验证跨块、跨 segment、后缀、末块和越界请求，并记录对齐回源区间及字节数。
- 验证上游截断、版本改变、淘汰及 PURGE 与填充竞争时，不发布未完成块、不混合版本、不重新发布被清理的代次。
- 验证正常退出恢复、异常退出失效及写入错误传播；性能测量与正确性验收分开，不预先承诺性能提升。
