# 部分对象缓存采用分段位图与对齐回源

采用 Plan A：对象信息与 segment 位图保存在缓存内部，按覆盖情况规划缺块，允许回源范围向 chunk 边界扩展。客户端只收到原始请求范围。具体流程见[部分对象缓存设计](../partial_object_cache.md)。

## 已确认约束

- 固定 1 MiB/chunk、64 chunk/segment，每段使用 64 bit 完成位图；末块按实际长度，不增加可调布局。
- 可共享、强 ETag、总长可确认、identity 编码的普通 GET 与单 Range 共用数据、位图和在途任务；支持后缀及开放结尾。多 Range、客户端条件请求等保留原有处理路径。
- 完全冷 GET 使用一次普通源 GET；已有数据或在途任务时先复用，仅对缺块执行对齐 Range 回源，合并相邻缺块。
- 位图用于规划，实际读取仍验证数据；淘汰或覆盖导致不可读时按 MISS 修正，条件更新不能清掉并发新填充。
- 每个响应固定源站和内容版本，不混版、不因换版在当前请求内重试。旧字节仍可取得则继续，否则终止；后续请求按新版重建。GET/Range 独立生成响应头和正文范围。
- PURGE 成功后新请求不能使用旧缓存代次，旧任务不得重新发布；已开始响应可按原版本继续，磁盘数据延后回收。
- 完整校验并提交的块可供命中，不要求每块同步落盘。正常退出并可靠保存后应可复用；异常恢复允许无法证明一致的缓存失效，但不得返回缺失、截断或错误版本的数据。
- 允许格式升级使旧缓存失效，不迁移旧内容；升级需考虑冷回源。

## 2026-11-03：响应完成与当前块填充分开

采用“流式发送＋独立完成当前块填充”。上游响应头校验通过后即提供 RWW，不等待整个块或扣留最后一字节；单字节及小 Range 在所需字节到齐后即可完成。只有完整校验、数据及目录提交后才置完成位。

最后读者结束或断开时，已开始块继续收尾；无人需要时不启动后续块或新回源，没有已开始块则取消。任务期限不延长，服务关闭、存储错误和 PURGE 发布围栏仍有效。尾部失败不发布该块，仍缺所需字节的读者失败；已完成响应不能撤回。

这一选择将客户端延迟与块提交分开，同时限制无需求的额外回源；不等于后台补全整个合并区间或对象。

## 验收

以真实 HTTP 的正文、头部、回源次数和 RWW 时序为主；现有缓存接口补充磁盘故障、并发竞争及恢复验证。覆盖 GET/Range 双向复用、单字节提前完成、当前块收尾、版本与 PURGE 围栏、正常重启及异常安全 MISS。性能结果单独测量，不预设收益。
