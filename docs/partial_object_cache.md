# 部分对象缓存（Partial Object Cache）

符合准入条件的普通 GET（含小对象）与单区间 Range 共用缓存块和在途回源，不另存整对象副本。采用 Plan A：按 segment 位图规划缺块，回源向块边界对齐，客户端只收到自己请求的字节。

## 数据模型

| 记录 | 内容与用途 |
| --- | --- |
| 对象元数据 | 总长、强 ETag、源站、变体、缓存代次和格式版本；确定一次响应使用的内容身份 |
| segment | 每段覆盖 64 个 chunk，保存一个 64 bit 完成位图；用于批量规划缺口 |
| chunk | 固定 1 MiB，末块按实际长度；数据独立存储、读取和淘汰 |

对象信息和段位图均为缓存内部记录。位图按需读取，由固定数量的条带锁协调更新，不维护每对象常驻位图，也不靠逐块读正文重建覆盖；64 bit 只是覆盖字段，不是整个元数据记录的大小。

完成位为 1 仍须验证实际目录、身份、长度、CRC 和新鲜度。块丢失或失效时按 MISS 补取，并条件修正位图，避免清掉并发新发布；位为 0 时也先查在途任务，避免重复回源。

## 请求流程

该路径要求可共享、强 ETag、已知总长及 identity 编码。支持单 Range 的指定、开放结尾和后缀范围；多 Range、客户端条件请求等走原有处理路径。

1. **发现对象。** 完全冷 GET 使用一次普通源 GET，不先 HEAD；冷 Range 通过共享 HEAD 获取对象信息。相容 GET/Range 可共用发现及填充任务。
2. **规划缺块。** 有缓存时读取相关段位图，验证并复用已完成块；缺块加入相容在途任务，无任务负责时再创建回源。
3. **对齐获取。** 连续缺块单次最多合并两块，不跨命中块、已认领区间或 segment 边界；Range 回源带 `If-Match`，限制为所选版本。末块不超出对象总长。
4. **独立响应。** 校验上游头部后按对象绝对偏移发送；GET 返回 200，Range 返回 206，各自生成头部并裁剪范围。不符合分块准入的 GET 沿用收到的源响应进入原有整对象缓存或透传。

例如客户端读 `[0.5, 2.5 MiB)`，块 0、2 已缓存且有效、块 1 缺失，只需回源 `[1, 2 MiB)`；客户端仍收到原来的 2 MiB。

## 合并回源与 RWW

| 机制 | 职责 |
| --- | --- |
| 请求合并 | 回源前原子登记任务，让相容的重叠请求共用生产者，覆盖源站尚未返回头部的阶段 |
| 缺块合并 | 把相邻缺块放进一次源 Range，减少源请求次数 |
| RWW | 多个读者按各自偏移读取确切 writer 已收到的字节，无须等待完整块 |

**1 MiB 是缓存与回源对齐单位，不是发送前必须积攒的大小。** 版本、范围、长度、编码及共享规则通过头部校验后即可输出；单字节请求也可提前完成。

客户端响应完成与缓存提交分开：

- 完整块校验通过后，先提交数据及目录，再置完成位；提交可读不等于逐块 `fsync`。
- 最后读者完成或断开后，已开始的当前块独立收尾；无人需要时不启动下一块，没有已开始块则取消。任务超时、关闭和存储错误仍可终止填充。
- 对齐尾部失败时不发布失败块，已提交前块保留；已完成的小响应无法撤回，仍缺所需字节的读者失败。

## 版本、失效与恢复

| 情况 | 行为 |
| --- | --- |
| 版本变化 | 响应固定所选版本，不拼接新版、不因换版在当前请求内重试；旧字节仍可取得则继续，否则终止，后续请求按新版重建 |
| PURGE | 新请求不能使用旧代次，旧任务失去发布权；已开始的响应可按原版本有界私有续流，慢读者可能需要补取历史块 |
| 正常重启 | 可靠保存后，验证检查点和数据，再复用已完成块；稀疏对象仍只补缺块 |
| 异常恢复 | 无法证明一致的数据安全 MISS；恢复的位图不能替代实际块校验 |
| 格式升级 | 不迁移旧缓存，不兼容记录失效后重新回源 |
